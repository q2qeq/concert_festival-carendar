## 3. 네이버 서치어드바이저 (사용자가 PDF로 저장 → 자동으로 읽음)
- Claude in Chrome은 `searchadvisor.naver.com`을 **안전 정책으로 차단**한다("not allowed due to safety restrictions"). 다른 브라우저·화면 제어로 돌아가서 열지 않는다. 브라우저로 시도하지 말고 바로 아래 순서로 간다.
- **먼저 `~/Downloads/네이버 서치어드바이저 정보/` 폴더를 본다.** 사용자가 2026-11-18부터 이 폴더에 매일 올려 둔다. 확장자가 없는 파일도 PDF일 수 있고, 파일 이름만으로는 날짜를 알 수 없다. 폴더에 없으면 다운로드 폴더의 `*네이버 서치어드바이저*.pdf`도 본다.
  ```bash
  ls -lt ~/Downloads/네이버\ 서치어드바이저\ 정보/ | head
  pdftotext -layout "<파일>" - | grep -v 'power_settings_new\|expand_more\|arrow_back_ios'
  ```
  - 파일 첫 줄의 저장 시각(예: `26. 11. 11. 오후 4:30`)과 본문의 기간(1일/7일/30일, 최근 업데이트일)을 확인한다. **3일 넘은 파일은 쓰지 않고**, traffic-log.md에 이미 반영된 날짜면 새 자료로 치지 않는다.
  - 인쇄한 PDF에는 표마다 첫 10줄만 담긴다. 11위 아래는 "미확인"으로 두고, 목록에 없다는 이유로 클릭이 없다고 판단하지 않는다.
  - 기간이 다른 파일끼리 숫자를 직접 비교하지 않는다.
  - 텍스트로 안 읽히는 그래프 값은 Read로 PDF를 이미지로 보고 눈대중임을 표시한다.
- 새 파일이 없으면 **사용자에게 이렇게 요청**하고, 기다리지 말고 나머지로 진행한다:
  > 서치어드바이저 > 리포트 > 콘텐츠 노출/클릭에서 기간 7일·30일을 각각 열고 ⌘P > PDF로 저장(다운로드 폴더 그대로) 해 주세요. 가능하면 수집 현황 화면도 같이요. 저장해 두면 다음 분석 때 자동으로 읽어요.
- 뽑을 항목: 클릭/노출/CTR(전기 대비), 키워드 상위, 콘텐츠(페이지)별 상위, 일별 추이, 수집·색인 현황(있으면).
- 자료가 없으면 네이버 항목은 "미확인"으로 두고 나머지로 진행한다. 추정으로 채우지 않는다. Vercel Referrers의 `search.naver.com`·`m.search.naver.com` 방문 수는 네이버 유입의 대체 지표로 따로 적는다.

## 4. 교차 분석
- **유입 구성**: 네이버 vs 구글 vs 직접/SNS 비중. (2026-11-07 주간은 방문자 608명 중 네이버 약 448, 구글 21.) 한쪽 쏠림이면 그 이유를 쿼리·페이지로 설명한다.
- **노출 대비 클릭**: 구글에서 노출 많고 클릭 적은 페이지 → 제목·description 개선 후보.
- **트래픽은 있는데 클릭이 없는 페이지**: 예매 링크 누락, CTA 위치 문제 후보. `audit:events` 결과와 대조.
- **쿼리 vs 콘텐츠 공백**: 검색어는 있는데 대응 페이지가 없거나 약한 것 (아티스트 내한, 취소·연기 이슈, 공연장 가는 법/주차). 새 글/페이지 후보.
- **수명 짧은 페이지**: 공연이 끝난 페이지로 아직 유입이 많은 것 → 다음 공연/관련 아티스트로 내부 링크 연결.
- **색인 문제**: 사이트맵 제출 대비 색인 수, 크롤링됨-미색인 사유.
- 표본이 작으면(클릭 수십 건 이하) 단정하지 말고 "추세 관찰 필요"로 쓴다.

## 4-0. 성과 기준과 효과 판정

### 매주 적는 기준 숫자
수익은 아직 판단하지 않는다(일 방문 약 100명, 2026-11-18 사용자 판단). 대신 수익에 가장 가까운 행동을 기준으로 삼는다.

- **공연 상세 방문자 100명당 예매 클릭** = 공연 페이지 예매 클릭 / 같은 기간 route `/events/[id]` 방문자 x 100
  - 예매 클릭: `npm run clicks:report -- 28`의 "성과 기준" 줄. 오늘을 뺀 어제까지 7일이다.
  - 방문자: `count_pageviews`에 filter `route eq '/events/[id]'`.
  - 기준선(2026-11-11~11-17): 예매 클릭 63 / 방문자 329 = **19.1**.
  - 클릭 집계는 2026-11-07에 시작했다. 11/4~11/10 주는 며칠이 비어 있어 비교에 쓰지 않는다.
- **재방문 비율**(2026-11-21 측정 시작, 두 번째 기준 숫자) = `npm run visits:report -- 30`의 "재방문 요약" 줄(어제까지 7일, 브라우저-일 기준).
  - 같이 적는 것: 주간 코호트의 "1주 뒤" 비율, 재방문이 들어온 곳 중 direct 비율(검색 없이 돌아온 사람), 알림을 켠 기기 수(`npm run push:report`).
  - 측정 첫 2주(~12/4)는 측정 전부터 오던 브라우저(legacy)가 섞여 높게 보인다. 기준선은 12/5~12/11 주로 잡는다.
  - 사파리 저장 기간 제한·인앱 브라우저 때문에 실제보다 낮게 나온다. 절대값보다 추세로 본다.
- 공연별로 볼 때는 예매·셔틀·그 밖을 나눠 본다. 셔틀이나 굿즈를 찾아온 페이지는 예매 클릭이 적어도 문제가 아니다. 방문자 30명 미만인 공연은 비율을 판단하지 않는다.

### 판정 규칙
1. 바꾼 날은 집계에서 뺀다. 전후 기간의 길이와 요일 구성을 맞춘다.
2. 기다리는 기간이 지나지 않았거나 양이 모자라면 **"판단 불가"**로 적는다. 효과가 있다고 쓰지 않는다.
3. 변화가 20% 안쪽이면 **"변화 없음"**으로 적는다.
4. 티켓 오픈, 공연 임박, 큰 소식이 같은 기간에 있던 페이지는 근거에서 뺀다. 가능하면 바꾸지 않은 비슷한 페이지와 비교한다.
5. 같은 숫자에 영향을 주는 변경은 한 번에 하나만 한다. 망가진 것을 고치는 버그 수정은 예외지만, 그 기간의 판정에는 같이 적는다.
6. 변경할 때 traffic-log.md에 **바꾼 날, 볼 숫자, 현재 값, 판정할 날**을 적는다.

### 서치콘솔 파일 찾기
사용자가 내려받은 파일은 다운로드 폴더에 이런 이름으로 떨어진다.
```bash
ls -lt ~/Downloads/https___jikgwannyang.com_-*  | head
# 실적: ...-Performance-on-Search-YYYY-MM-DD.zip
# 색인 요약: ...-Coverage-YYYY-MM-DD.zip
# 색인 사유별 URL: ...-Coverage-Drilldown-YYYY-MM-DD (n).zip  (사유마다 한 개)
```
- 압축은 스크래치 폴더에 파일마다 새 폴더를 만들어 푼다(다운로드 폴더 안에서 풀지 않는다). 안의 파일 이름이 한글(`테이블.csv`, `차트.csv`, `메타데이터.csv`)이라 `unzip`은 실패한다. `ditto -x -k <zip> <폴더>`를 쓴다.
- 색인 사유별 zip(Coverage-Drilldown)은 지금 빌드와 대조하는 스크립트로 먼저 돌린다. `npm run build` 뒤 저장소 루트에서:
  ```bash
  .claude/skills/traffic-feedback/check-index-export.sh "<Coverage-Drilldown zip>" <스크래치 폴더>
  ```
  주소마다 빌드에 있는지, noindex인지, 사이트맵에 있는지, 몇 페이지가 링크하는지를 낸다. 플러그인의 미색인 판단 순서(빠져야 할 주소를 먼저 가르고, 남은 것은 발견이 약한지 본다)를 그대로 숫자로 보여 준다.
  - 2026-11-17 결과(발견됨-미색인 105): 사이트맵에 있고 색인 대상 91, 일부러 사이트맵에서 뺀 지난 공연 10(셋리스트 없는 7일 지난 공연, astro.config), noindex 태그·일정 3, 리디렉션된 옛 주소 1. 사이트맵에 있는 91건 중 링크하는 페이지가 2개 이하인 건 `/artists/` 하나뿐이었다. 즉 내부 링크 부족이 원인이 아니고 사이트 단위 크롤 수요 문제라는 진단과 맞다. 다음 결과는 이 숫자와 비교한다.
- 날짜가 traffic-log.md에 이미 반영된 날이면 새 자료로 치지 않는다. 새 파일이 없으면 사용자에게 요청한다:
  > 서치콘솔 > 실적(28일, 이전 기간과 비교)과 색인 > 페이지에서 오른쪽 위 '내보내기 > CSV 다운로드'를 눌러 주세요. 색인 화면은 미색인 사유를 하나씩 눌러 그 화면에서도 내보내 주세요.

### 스킬별로 볼 것
- **search-console-data-review**: 계산 과정을 보여 주는 게 장점이니 숫자를 그대로 traffic-log에 옮긴다.
  - 실적 표: 순위 4~15위인데 노출이 많은 검색어(조금만 오르면 클릭이 붙는 것), 기대보다 CTR이 낮은 페이지, 직전 기간 대비 클릭이 빠진 페이지.
  - 색인 표: 사유별 개수와 유형(공연·블로그·공연장·일정·태그·도구). 2026-11-17에는 발견됨-미색인 105건이 **모두 최종 크롤링 1970-01-01**(한 번도 방문 안 함)이었다. 다음 분석 때 이 숫자가 줄었는지, 최종 크롤링 날짜가 찍힌 URL이 생겼는지 본다.
  - 웹 화면에서 내보낸 실적 파일은 검색어와 페이지가 따로 나와서 '같은 검색어를 두 페이지가 나눠 먹는지'(카니벌라이제이션)는 판단할 수 없다. 이건 "확인 못 함"으로 둔다.
- **technical-seo-code-audit**: 이 저장소를 읽게 한다. 우리 쪽에서 특히 볼 곳:
  - `src/layouts/BaseLayout.astro`의 `<head>`(제목·설명·캐노니컬·noindex 조건)
  - `astro.config.*`(사이트 주소, trailingSlash, 사이트맵, `sitemapDropNoindex`로 noindex 페이지가 사이트맵에서 빠지는지)
  - `vercel.json` 리디렉션(한글 경로는 퍼센트 인코딩해야 맞는다), `public/robots.txt`, 404 페이지
  - 내부 링크가 쿼리 주소(`?venue=`)로 새지 않는지(도구 링크는 `#venue=` 해시가 규칙, 717e9ae)
  - 코드를 읽기만 한다. 고치는 건 사용자가 "반영해줘"라고 할 때.

  - 제목·설명 후보가 영어식이면 그대로 쓰지 않는다. 사이트 문체(해요체, 과장 없음, 이모지 없음)로 바꾸고, 공연명·날짜·공연장은 events.json의 값만 쓴다.
  - 경쟁 페이지 비교는 사용자가 주소를 줄 때만 한다(플러그인이 스스로 고르지 않는다).

### 이 플러그인이 다루지 않는 것
- 네이버는 다루지 않는다. 유입의 약 70%가 네이버라서 네이버 판단은 3절(서치어드바이저 PDF)로 따로 한다. 구글 기준 권고를 네이버에도 맞는다고 쓰지 않는다.
- 플러그인이 "가정"이라고 표시한 것은 근거로 쓰지 않는다. traffic-log에는 파일·페이지에서 확인된 것만 적는다.
- 사이트 전체 크롤 수요 문제(외부 인기·신뢰)는 코드로 바로 고쳐지지 않는다. 새 URL 종류를 늘리는 제안(아티스트 허브 등)이 나오면 traffic-log 11/17의 보류 이유와 대조한 뒤에 권한다.

## 5. 출력 형식
채팅에 아래 순서로 간결하게:
1. **한 줄 요약**: 지난 기간 대비 무엇이 달라졌나
2. **숫자 표**: 소스별 클릭/노출/방문자와 전기 대비 증감, **공연 상세 방문자 100명당 예매 클릭** (확인 못 한 칸은 "미확인")
3. **잘 되는 것 / 안 되는 것** 각 2~3개, 근거 숫자 포함
4. **다음 행동 3~5개**: 각각 `무엇을 / 왜(근거) / 어디를 고치나(파일·페이지) / 볼 숫자와 판정할 날` 한 줄씩, 영향 큰 순서
5. **지난 권고 이행 여부**: traffic-log.md의 이전 항목 중 실행된 것/안 된 것. 효과는 4-0절 기준으로 "효과 있음/변화 없음/판단 불가" 중 하나로 적는다

그리고 `src/data/traffic-log.md` 맨 위에 날짜 헤더로 요약(숫자 표 + 행동 목록)을 추가한다. 기존 기록은 지우지 않는다.

## 규칙
- 읽기 전용 분석이 기본. 사이트 수정은 사용자가 "반영해줘"라고 할 때만 하고, 그 경우 프로젝트의 자동 커밋·푸시 규칙(.claude/ 제외, force push 금지)을 따른다.
- 개인정보·로그인 정보는 기록하지 않는다.
- 숫자는 화면에서 읽은 값만 쓴다. 못 읽은 값을 짐작해서 채우지 않는다.
- 애드센스/제휴 판단은 클릭 데이터가 2~3주 이상 쌓였을 때만 언급한다.
