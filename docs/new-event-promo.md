# 신규 공연 홍보 장치 (2026-11-09)

새 공연이 사이트에 올라오면 7일 동안 아래 장치가 자동으로 켜진다. 전부 `events.json`의 두 필드로 제어한다.

| 필드 | 뜻 | 효과 |
| --- | --- | --- |
| `addedAt` (yyyy-mm-dd, KST) | 사이트에 처음 올린 날 | 카드 "신규" 배지, 홈 "NEW THIS WEEK" 섹션 (7일간) |
| `promoBanner` (한 줄 문구) | 상단 배너 문구 | 모든 페이지 헤더 아래 배너 (addedAt 7일간, 가장 최근 1건) |

- 새 공연을 **추가**할 때만 `addedAt`을 넣는다. 기존 공연에는 없다. `scripts/fetch-kopis.mjs`는 자동으로 넣는다.
- 배너는 화제성 큰 공연에만 쓴다(`promoBanner`). 닫으면 그 공연 id를 localStorage에 기억해 다시 안 뜬다. 모달 팝업은 쓰지 않는다(이탈·애드센스 정책 위험).
- 배지·섹션은 **빌드 시점** 기준이라, 7일이 지나도 다음 배포 전까지는 남아 있을 수 있다. 매일 도는 자동화가 푸시하므로 보통 하루 안에 정리된다.

## 같이 켜지는 것

- **발표 대기 카드** (`AnnounceWatch`): 공연장이 "추후 발표"이거나 티켓 오픈 일정이 없는 공연 페이지에 자동 표시. 찜(♡)으로 연결되고, 찜한 공연의 새 소식(`updates`)은 `/my`와 홈에서 알려준다. 서버에 아무것도 저장하지 않는다.
- **가고 싶어요** (`WantButton`, `api/want.js`): 공연별 숫자 하나를 Redis 해시 `want:counts`에 센다. 누른 기록은 브라우저(localStorage)에만 남는다. Redis 환경변수가 없으면 버튼이 숨는다. 상위 목록은 `GET /api/want?top=20`. 숫자는 3 이상일 때만 보여준다.
- **공유 카드** (`npm run og:cards [-- <id>]`): 글자만 쓰는 1200x630 PNG를 `public/og/<id>.png`로 만든다. 포스터가 없는 공연의 og:image로 쓰인다. 한글 글꼴이 필요해서 macOS 로컬에서 만들어 커밋한다(서버 빌드에서는 안 만든다).
- **홍보 문안** (`npm run promo:copy [-- <id>]`): 커뮤니티·X·카톡에 직접 올릴 문안을 출력한다. 자동 게시는 하지 않는다(커뮤니티 규칙 위반·차단 위험). 올릴 때는 해당 커뮤니티의 홍보 규칙을 먼저 확인한다.
- 블로그 글의 og:image는 본문 첫 이미지(`/…`로 시작하는 마크다운 이미지)를 쓴다.
