# 블로그 글 규칙 (2026-11-12)

블로그 글(`src/content/posts/YYYY-MM-DD-<영문-슬러그>.mdx`, 2026-11-12까지의 옛 글은 `postN.mdx`)을 올릴 때 지키는 규칙. 사람이 쓰든 자동 작업이 쓰든 똑같이 적용한다.
올리기 전에 `npm run audit:posts`를 돌려 ERROR가 0인지 확인한다(2026-11-12 이후 글이 규칙을 어기면 종료 코드 1).

## 1. 사진은 최소 한 장

- 본문에 사이트 안 이미지 `![설명](/경로)`를 **최소 한 장** 넣는다. 첫 이미지는 글의 og:image(공유 썸네일)로도 쓰인다.
- 쓸 수 있는 사진:
  - 공연 포스터 `/posters/<공연 id>.webp` - 공연을 다루는 글의 기본값. 포스터가 없으면 `npm run posters:cache`로 먼저 받아 둔다.
  - 저작권이 열린 사진(Wikimedia Commons의 CC 라이선스 등)을 `public/images/blog/`에 저장해 쓸 때는 바로 아래에 촬영자·출처 링크·라이선스를 적고, 이번 공연 사진이 아니면 그렇다고 밝힌다(예: post54).
  - 포스터가 없는 공연은 공유 카드 `/og/<id>.png`(`npm run og:cards -- <id>`)를 쓴다.
- 언론 기사 사진, SNS 사진, 출처를 알 수 없는 사진은 쓰지 않는다.
- 이미지를 넣기 전에 직접 열어 봐서 정말 그 공연 포스터인지 확인한다. KOPIS 포스터 자리에 기사 캡처가 올라와 있던 일이 있다(에픽하이, 2026-11-12).
- alt 텍스트에는 무슨 사진인지(공연명 + 포스터/사진)를 적는다.

## 2. 티켓팅·공연장 도구 링크를 넣는다

글 내용에 맞는 도구를 본문에 자연스럽게 링크한다. 최소 하나, 보통 두세 개.

| 상황 | 링크 |
| --- | --- |
| 예매 오픈 전·매진·취소표 | [티켓팅 시계](/ticketing-clock/), [티켓팅 연습 게임](/practice/), [티켓팅 준비 점검](/ticketing-check/) |
| 예매 일정 모음 | [티켓오픈 일정](/ticket-open/) |
| 저녁 공연·지방 관객 | [막차 계산기](/return-trip/), [직관 비용 계산기](/trip-cost/) |
| 공연장 이야기 | 공연장 페이지 `/venues/<slug>/` (slug는 `src/lib/venues.ts`의 `VENUE_SLUG_MAP`. venues.json에 없는 공연장은 페이지가 없으니 링크하지 않는다) |
| 여러 도구를 한 번에 | [도구 모음](/tools/) |

- 공연 페이지 `/events/<id>/` 링크는 지금처럼 꼭 넣는다(글 상단 티켓오픈 박스가 이 링크로 붙는다).
- 도구 링크는 글 끝에 목록으로 몰아 넣기보다, 필요한 문단에 한두 줄로 넣는다.
- 글 끝에는 "다 읽었다면" 도구 선반(`PostToolShelf`)이 자동으로 붙는다. 본문에 처음 나온 예정 공연을 기준으로 공연 페이지·오픈 카운트다운·막차/비용 계산기(공연장 채움)를 보여 주니, 그 공연의 `/events/<id>/` 링크를 본문 앞쪽에 두면 된다.

## 3. 기존 규칙 (그대로 유지)

- 숫자(가격·일정·회차)는 원문·예매처·KOPIS에서 확인한 것만 쓴다. 출처끼리 다르면 빼거나 "예매처에서 확인"으로 적는다.
- 글 끝에 `---` 구분선, 변동 가능 안내 문구, 실제로 연 출처 링크 목록을 둔다.
- 새 글 파일 이름은 `YYYY-MM-DD-<영문-슬러그>.mdx`(소문자·숫자·하이픈). `postN` 번호는 다른 자동 작업과 겹쳐 덮어써진 적이 있어 더 쓰지 않는다. 옛 글 이름은 주소가 바뀌므로 그대로 둔다. `npm run audit:posts`가 2026-11-13 이후 글의 이름을 검사한다.
- 문체는 1인칭 대화체, 이모지·상투적인 AI 문체는 쓰지 않는다.
