# 블로그 글 규칙 (2026-11-12)

블로그 글(`src/content/posts/YYYY-MM-DD-<영문-슬러그>.mdx`, 2026-11-12까지의 옛 글은 `postN.mdx`)을 올릴 때 지키는 규칙. 사람이 쓰든 자동 작업이 쓰든 똑같이 적용한다.
올리기 전에 `npm run audit:posts`를 돌려 ERROR가 0인지 확인한다(2026-11-12 이후 글이 규칙을 어기면 종료 코드 1).

## 1. 사진은 최소 한 장

- 본문에 사이트 안 이미지 `![설명](/경로)`를 **최소 한 장** 넣는다. 첫 이미지는 글의 og:image(공유 썸네일)로도 쓰인다.
- 쓸 수 있는 사진:
  - 공연 포스터 `/posters/<공연 id>.webp` - 공연을 다루는 글의 기본값. 포스터가 없으면 `npm run posters:cache`로 먼저 받아 둔다.
  - 저작권이 열린 사진(Wikimedia Commons의 CC 라이선스 등)을 `public/images/blog/`에 저장해 쓸 때는 바로 아래에 촬영자·출처 링크·라이선스를 적고, 이번 공연 사진이 아니면 그렇다고 밝힌다(예: post54).
  - 포스터가 없는 공연은 공유 카드 `/og/<id>.png`(`npm run og:cards -- <id>`)를 쓴다.
- 언론 기사 사진, SNS 사진, 출처를 알 수 없는 사진은 쓰지 않는다.
- 이미지를 넣기 전에 직접 열어 봐서 정말 그 공연 포스터인지 확인한다. KOPIS 포스터 자리에 기사 캡처가 올라와 있던 일이 있다(에픽하이, 2026-11-12).
- alt 텍스트에는 무슨 사진인지(공연명 + 포스터/사진)를 적는다.

## 2. 티켓팅·공연장 도구 링크를 넣는다

글 내용에 맞는 도구를 본문에 자연스럽게 링크한다. 최소 하나, 보통 두세 개.

| 상황 | 링크 |
| --- | --- |
| 예매 오픈 전 | [티켓팅 시계](/ticketing-clock/), [티켓팅 연습 게임](/practice/), [티켓팅 준비 점검](/ticketing-check/) |
| 예매 오픈이 지남·매진·취소표 | [취켓팅 연습](/practice/?stage=cancel), [티켓팅 시계](/ticketing-clock/) |
| 예매 일정 모음 | [티켓오픈 일정](/ticket-open/) |
| 저녁 공연·지방 관객 | [막차 계산기](/return-trip/), [직관 비용 계산기](/trip-cost/) |
| 공연장 이야기 | 공연장 페이지 `/venues/<slug>/` (slug는 `src/lib/venues.ts`의 `VENUE_SLUG_MAP`. venues.json에 없는 공연장은 페이지가 없으니 링크하지 않는다) |
| 여러 도구를 한 번에 | [도구 모음](/tools/) |

- 연습 링크는 글을 쓰는 날의 티켓 오픈을 기준으로 고른다(2026-11-18). 글의 공연이 오픈 전이면 `/practice/`, 오픈이 지났으면(오픈 단계가 모두 지났거나 예매 링크가 걸려 있으면) `/practice/?stage=cancel`이다. 오픈 전에 쓴 글은 오픈이 지나면 4절대로 바꾼다.
- 공연 페이지 `/events/<id>/` 링크는 지금처럼 꼭 넣는다(글 상단 티켓오픈 박스가 이 링크로 붙는다).
- 도구 링크는 글 끝에 목록으로 몰아 넣기보다, 필요한 문단에 한두 줄로 넣는다.
- 글 끝에는 "다 읽었다면" 도구 선반(`PostToolShelf`)이 자동으로 붙는다. 본문에 처음 나온 예정 공연을 기준으로 공연 페이지·오픈 카운트다운·막차/비용 계산기(공연장 채움)를 보여 주니, 그 공연의 `/events/<id>/` 링크를 본문 앞쪽에 두면 된다.

## 3. 기존 규칙 (그대로 유지)

- 숫자(가격·일정·회차)는 원문·예매처·KOPIS에서 확인한 것만 쓴다. 출처끼리 다르면 빼거나 "예매처에서 확인"으로 적는다.
- 글 끝에 `---` 구분선, 변동 가능 안내 문구, 실제로 연 출처 링크 목록을 둔다.
- 새 글 파일 이름은 `YYYY-MM-DD-<영문-슬러그>.mdx`(소문자·숫자·하이픈). `postN` 번호는 다른 자동 작업과 겹쳐 덮어써진 적이 있어 더 쓰지 않는다. 옛 글 이름은 주소가 바뀌므로 그대로 둔다. `npm run audit:posts`가 2026-11-13 이후 글의 이름을 검사한다.
- 문체는 1인칭 대화체, 이모지·상투적인 AI 문체는 쓰지 않는다.

## 4. 티켓 오픈이 끝난 글은 취켓팅으로 바꾼다 (2026-11-17)

오픈이 끝난 뒤에 글을 찾아오는 사람은 대부분 취소표를 노리는 사람이다. 그래서 글의 공연(본문에 처음 나온 예정 공연)의 오픈 단계가 모두 지났고 공연은 아직 남았으면, 글을 취켓팅용으로 고친다.

- 대상 찾기: `npm run posts:cancel`. `!!`가 붙은 글이 대상이다. 본문에 `/practice/?stage=cancel` 링크가 들어가면 "이미 바꾼 글"로 센다.
  - `!! 되돌릴 글`은 취켓팅 링크가 있는데 그 공연이 오픈 전인 글이다. 글의 공연이 잘못 잡힌 경우가 많으니, 글이 실제로 다루는 공연의 `/events/<id>/` 링크를 첫 문단에 넣는다.
  - `?? 판매 상태 확인 필요`는 글에 나온 공연 중 예매처를 열어 본 기록이 없거나 7일이 지난 것이다.
- 고치기 전에 예매처 상품 페이지를 실제로 열어 판매 상태를 확인한다(2026-11-18). 데이터의 오픈 시각·예매 링크만 보고 쓰지 않는다.
  - 여는 방법: 예스24는 스크립트로 열어도 된다(페이지의 `HidPerfSaleState`와 "예매하기"·"판매종료" 문구). 멜론티켓·티켓링크·NOL은 Claude in Chrome으로 한 페이지씩 연다.
  - 읽는 법: "예매하기" 버튼이 살아 있으면 예매 가능, "오픈 예정"이면 오픈 전, "판매가 종료되었어요"·"판매가 종료된 상품입니다"면 판매 종료다. NOL은 날짜를 고르면 등급별 잔여석이 나온다(전 회차·전 등급 0이면 매진). 잔여석을 안내하지 않는 상품도 있다.
  - **NOL의 "예매대기"는 오픈 전이라는 뜻이 아니다.** 매진된 좌석에 대기를 걸어 두는 서비스 표시다(11/16 한로로 글에서 잘못 읽었다).
  - 확인한 결과는 events.json의 `saleState`(`upcoming`·`open`·`soldout`·`closed`)와 `saleCheckedAt`(오늘 날짜)에 적는다. 열어 보지 못한 공연에는 적지 않는다.
  - 글에는 확인한 날짜와 함께 본 것만 쓴다("11월 18일 밤 기준 R석 16석"). 매진·잔여석은 금방 바뀌니 날짜 없이 쓰지 않는다.
  - 판매 종료(`closed`)인 공연은 취켓팅을 안내하지 않고, 종료됐다고 적는다.
  - 오픈 시각이 데이터에 없어도 예매처 상품 링크가 걸린 공연의 글은 대상이다(2026-11-18). 공연 페이지가 취켓팅 안내로 바뀌는 기준과 같다.
  - 본문의 `/practice/` 링크는 지우지 말고 `/practice/?stage=cancel`로 바꾼다. 링크 글자도 "취켓팅 연습"으로 맞춘다.
- 자동으로 되는 것: 글 상단 박스는 오픈이 끝나면 "취소표 노리기"와 취켓팅 체크리스트로, 글 끝 선반은 예매 중인 공연이면 "취켓팅 연습" 카드로 바뀐다(`OpenCountdown`, `PostToolShelf`). 본문은 바뀌지 않으니 아래를 손으로 한다.
- 본문에서 할 일:
  1. 오픈 전 기준으로 쓴 문장("○일에 오픈해요", "준비물" 등)은 지우지 말고 과거형으로 고치거나, 그 문단 앞에 `(11월 17일 덧붙임) 티켓 오픈은 끝났어요.`처럼 날짜를 밝힌 한 줄을 단다.
  2. 출처 목록 바로 앞(`---` 위)에 `## 취켓팅을 노린다면` 단락을 넣는다. 들어갈 것: 지금 예매처(`ticketLinks`의 상품 페이지), [취켓팅 연습](/practice/?stage=cancel), [티켓팅 시계](/ticketing-clock/) 링크.
  3. 그 공연만의 사실이 있으면 같이 적는다: 매진·잔여석·추가 회차 보도, 예매처 공지의 취소 마감 시각·무통장 입금 기한, 양도 금지·본인 확인 입장 같은 규칙. 원문(공식 공지·예매처·기사)을 열어 이번 공연 것인지 확인한 것만 쓴다.
- 쓰지 않는 것: "○시에 취소표가 많이 풀려요" 같은 근거 없는 팁, 매크로·대리 예매 안내, 확인 안 된 매진 여부. 공연마다 같은 문장을 복사해 붙이지 않는다(AI 티가 난다).
- 제목·파일 이름·`pubDate`는 그대로 둔다(주소와 색인이 바뀌지 않게). `description`은 바꿔도 된다.
- 고친 뒤 `npm run audit:posts`, `npm run build`를 통과시키고 커밋 메시지에 "취켓팅 전환: <글 이름들>"을 적는다.

## 5. 공연이 끝나면 실황·반응 글을 쓴다 (2026-11-18)

공연이 끝난 뒤에 공연 페이지를 찾는 사람은 셋리스트와 현장 이야기를 보러 온다. 그래서 끝난 공연 가운데 고른 것은 후기 글로 정리한다.

- 대상 찾기: `npm run posts:after`(최근 10일 안에 끝난 공연). `!!`는 공연 전에 우리 글이 다뤘거나 수요가 높은 공연이다. 여기부터, 끝난 지 얼마 안 된 순으로 쓴다.
- 쓰는 때: 공연 마지막 날 다음 날부터 7일 안. 그 뒤에는 기사와 셋리스트가 더 나오지 않으니, 쓸 재료가 없으면 건너뛴다.
- 이 글은 **우리가 직접 본 관람 후기가 아니다.** 보도와 공식 자료, 공개된 반응을 모아 정리한 글이다. "제가 가 보니", "현장에서 느낀" 같은 문장을 쓰지 않는다. 글 앞쪽에 "보도와 공식 자료를 모아 정리했어요"라고 한 줄 밝힌다.
- 넣을 것(확인된 것만, 없으면 그 항목은 뺀다):
  1. 실제 셋리스트 - setlist.fm이나 공식 발표. 회차마다 다르면 회차를 밝힌다. 곡 제목만 적고 가사는 옮기지 않는다.
  2. 숫자 - 관객 수, 매진 여부, 러닝타임, 게스트. 기사 원문에서 확인하고 출처끼리 다르면 쓰지 않는다.
  3. 현장 이야기 - 언론 리뷰와 주최 측·아티스트 공식 채널이 전한 장면, 멘트, 깜짝 발표(추가 공연, 다음 투어).
  4. 관객 반응 - 커뮤니티·SNS 반응은 "이런 반응이 많았어요" 정도로 요지만 옮긴다. 개인 글을 통째로 옮기거나 아이디를 적지 않는다. 운영 문제(입장 지연, MD 품절, 귀갓길)는 여러 곳에서 확인될 때만 쓰고, 한쪽 편을 들지 않는다.
  5. 다음 일정 - 같은 아티스트의 다음 한국 공연이나 같은 공연장의 다음 공연. `/events/<id>/`로 링크한다.
- 영상과 사진: 영상은 아티스트·주최 측 **공식 채널**에 올라온 것만 링크한다. 관객이 찍은 직캠은 링크하지 않는다. 사진은 1절 그대로다(포스터, 위키미디어 공용 CC). 언론·SNS의 공연 사진은 쓰지 않는다.
- 파일 이름은 `YYYY-MM-DD-<아티스트>-<도시나 공연장>-review.mdx`, `tags`에 `"공연 후기"`를 꼭 넣는다(후보 스크립트가 이 태그로 "후기 글 있음"을 센다).
- 본문에서 그 공연을 `/events/<id>/`로 링크한다. 끝난 공연이라 글 상단 티켓오픈 박스는 붙지 않는다.
- 도구 링크(2절)는 다음 공연 쪽으로 건다. 예: 다음 한국 공연이 오픈 전이면 [티켓팅 연습](/practice/)과 [티켓오픈 일정](/ticket-open/), 같은 공연장의 다음 공연이 있으면 공연장 페이지와 [막차 계산기](/return-trip/).
- 공연 페이지도 같이 채운다. 확인한 셋리스트는 events.json의 `setlists`에(`label`, `date`, `venue`, `songs`, `sourceUrl`), 관객 수·추가 공연 같은 소식은 `updates`에 날짜와 출처와 함께 넣는다. 공연 페이지 '이 공연이 언급된 이슈'에 글이 저절로 걸린다.
- 쓸 재료가 셋리스트뿐이면 글을 쓰지 않고 공연 페이지의 `setlists`만 채운다. 얇은 글을 늘리지 않는다.
- 고친 뒤 `npm run audit:posts`, `npm run audit:events`, `npm run build`를 통과시키고 커밋 메시지에 "공연 후기: <공연 id>"를 적는다.
