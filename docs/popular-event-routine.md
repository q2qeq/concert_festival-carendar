# 인기 공연 디벨롭 루틴

방문이 많은 공연일수록 공연 페이지와 블로그 글을 더 깊게 만든다. 주 1회, 아래 순서로 한다.

## 1. 후보 뽑기

1. Vercel Web Analytics > Top Pages를 최근 7일로 놓고 CSV를 내려받는다 (Page, Visitors, Total).
2. 후보를 본다.

```bash
npm run popular:events -- "<CSV 경로>" 12 --must=<꼭 포함할 공연 id>
```

3. 우선순위는 필수 > 글 없음 > 정보 부족 > 방문자 많은 순이다. 이미 끝난 공연은 자동으로 빠진다.
4. 방문자가 3명 미만인 공연은 건너뛴다. 표본이 너무 작다.

## 2. 조사 (공연 하나당)

- 이미 있는 데이터(`events.json`의 description·sources·updates)를 먼저 읽고, 그 출처 URL을 직접 열어서 사실을 확인한다. 검색 요약만 보고 쓰지 않는다.
- 찾을 것: 가격과 예매 일정, 러닝타임·관람연령, 투어 전체 일정과 서울의 위치, 지난 내한 이력, 새 앨범·소속사·투어 소식, 공연장 정보.
- 출처 두 곳이 어긋나면 쓰지 않거나 "엇갈려요"라고 적는다. 확인 못 한 것은 추측으로 채우지 않는다. 글에 "기사에 없어서 모르겠어요"라고 적는 것은 괜찮다.
- 기존 공연 페이지 내용이 틀렸으면 이번에 같이 고친다 (후지이 카제 "첫 내한" 오류가 그 사례).

## 3. 공연 페이지 보강 (`src/data/events.json`)

- `description`, `funFacts`, `updates`(날짜·출처 포함)를 채우고, 정보가 채워졌으면 "상세 정보는 아직 부족해요" 류의 `note`를 지운다.
- 가격·러닝타임·예매 규칙처럼 확인된 값은 `note`나 `description`에 넣는다.
- 글에서 다루는 `id`는 글 본문에서 `/events/<id>/`로 링크한다 (후보 스크립트가 이 링크로 "글 있음"을 판단한다).

## 4. 블로그 글 (`src/content/posts/postN.mdx`)

- **번호**: `npm run popular:events`가 알려주는 다음 번호를 쓰기 직전에 `ls src/content/posts | sort -V | tail -2`로 다시 확인한다. 다른 스케줄 작업과 번호가 겹치면 덮어써진다 (2026-11-08에 실제로 post27이 덮어써졌다). **쓰자마자 바로 커밋한다.**
- 제목은 "무엇이 새로 나왔는지"를 담는다. 공연 하나당 글 하나, 새 소식(투어 개막, 일정 변경, 앨범, 취소 등)이 각도다. 가격·예매만 반복하는 글은 피한다.
- 사진은 사이트에 이미 올려둔 공연 포스터(`/posters/<id>.webp`) 한 장만 쓴다. 언론·SNS 사진은 가져오지 않는다. 캡션에 출처를 적는다.
- 맨 아래에 참고한 출처 링크를 적는다. 공연 일정이 바뀔 수 있다는 안내도 넣는다.
- 톤은 기존 글과 같게 한다 (해요체, 과장 없이).

## 5. 마무리

1. `npm run build`가 통과하는지 확인한다.
2. 커밋하고 main에 푸시한다 (`.claude/` 제외, force push 금지).
3. 공연마다 따로 커밋하면 충돌과 번호 겹침이 줄어든다.

## 한계

- 트래픽 CSV는 사람이 Vercel에서 내려받아야 한다. 자동으로 가져오는 길이 없다.
- 7일 표본이 작아서 순위 차이가 1~2명이면 우연일 수 있다. 며칠 치를 모아서 보면 더 낫다.
