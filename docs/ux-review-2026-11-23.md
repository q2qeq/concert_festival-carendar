# UX/UI 피드백과 디벨롭 초안 (2026-11-23)

실제 사이트(jikgwannyang.com)를 데스크톱(1440px)과 휴대폰(iPhone 14)으로 열어 본 결과다.
본 화면: 홈, 공연 상세(요아소비), 캘린더 구독, 공연장(고척스카이돔), 블로그 글(원더리벳 후기), 티켓팅 연습, 도구 모음.
기준은 두 가지다. **AI가 만든 티가 나는가**, 그리고 **진지한 정보 사이트로 믿을 만한가**.

## 1. 요약

- 색·서체·여백은 11/14 개편 뒤 많이 정리됐다. 고양이 색 세 가지, 따뜻한 검정 바탕, 숫자 서체는 이 사이트만의 얼굴이 됐다.
- AI 티가 남은 곳은 **구조**다. 번호 붙은 카드 격자, 왼쪽 색 띠 박스, "1·2·3 단계 + 폰 목업" 홍보 블록, 가운데 "더 알아보기" 구분선은 생성형 랜딩 페이지에서 그대로 나오는 틀이다.
- 문구의 AI 티는 **"한눈에", "~해 드려요", 판촉 형용사**다. "한눈에"가 화면·메타 설명에 13번 나온다.
- 진지함을 가장 많이 깎는 것은 **정보 위계**다. 티켓팅 사이트인데 가장 큰 숫자가 145일 뒤 공연일 D-day이고, 정작 중요한 티켓오픈 D-7은 작다. 그리고 근거가 약한 "인파 예상" 판단이 규칙 밖 초록색 박스로 크게 나온다.

### 3-3. 판단·예측 문구

"지난 회차와 비교"의 **인파 예상**은 "자리가 많을 수 있어요", "먼저 빠질 가능성이 커요"처럼 추측을 크게, 색 배지로 보여 준다. 근거는 관객 수 두 개와 경기장 좌석 수인데, 박스 안 문장도 "판매 좌석 수는 발표되지 않았어요"라고 스스로 인정한다.
진지한 사이트라면 **확인된 숫자(지난 회차 관객 수, 매진 시점, 출처)만 표로 보여 주고 결론은 독자에게 맡긴다.** 예측 배지는 지운다.

## 5. 디벨롭 초안

원칙: **사람이 손으로 만든 정보 사이트처럼 보이게 한다.** 즉, 틀보다 내용, 꾸밈보다 출처, 예측보다 확인된 숫자.
한 단계씩 끝내고 화면 캡처(`.claude/tools/shots/clip.mjs`)로 확인한 뒤 다음으로 간다.

### 1단계 — 진지함을 깎는 것 걷어내기 (반나절, 디자인 결정 없음)

1. 인파 예상 배지·초록 색·막대 제거, 지난 회차는 표(연도·장소·회차·관객 수·출처)로 (A4, 3-3, B8).
2. "더 알아보기" 구분선, 도구 목록 번호 제거, 카드 격자 → 목록 한 줄 (A1, A5).
3. 왼쪽 색 띠 박스 3곳을 위쪽 1px 선 또는 배경만으로 (A3).
4. 3-1·3-2 문구 일괄 교체. "한눈에"·"드려요"는 메타 설명까지 전부.
5. 빈 광고 칸 높이 0, 신규 띠는 홈·일정에서만 (B5, B6).

완료 기준: `grep -rn "한눈에\|드려요" src/pages src/components` 0건, `#7ed957` 0건, `npm run build` 통과.

### 2단계 — 정보 위계 바로잡기 (1~2일)

1. 티켓오픈 우선 표시: 홈 첫 화면·공연 상세 위쪽에서 오픈 전 공연은 오픈 시각이 가장 큰 숫자 (B1).
2. 휴대폰 공연 상세의 중복 버튼 정리: 예매·찜·캘린더를 한 번씩만 (B3).
3. 소개문 규칙 바꾸기: 표에 있는 사실을 되풀이하지 않는다. `docs/event-page-review.md`와 `audit:events`에 "소개문에 가격·연령이 들어가면 WARN" 추가 (B4).
4. 데스크톱 목차는 5개 이하 큰 구역만, 본문 옆에 붙인다 (A6).
5. 홈 첫 화면 제목 잘림 수정 (B2).

완료 기준: 요아소비·아지캉·indigo la End 세 공연을 휴대폰으로 열었을 때 첫 화면에 "오픈 시각 · 예매처 · 예매 버튼"이 다 보인다.
측정: 주간 성과 판정(월요일)에서 공연 상세 → 예매 클릭률을 2주 전후로 비교한다(`traffic-feedback` 4-0절 기준).

### 3단계 — 캐릭터와 말투 정하기 (사용자 결정 필요)

캐릭터는 이 사이트의 얼굴이라 지우자는 것은 아니다. 다만 지금은 "새벽이가 짚어주는", "노을이가 챙기는", "직관냥이 찾은"처럼 **본문 제목마다 화자가 바뀐다.** 정보를 읽으려는 사람에게는 이 화자 설정이 소음이고, 생성형 서비스의 "친근한 어시스턴트" 말투와 겹친다.

선택지:
- **(권장) 얼굴만 남긴다.** 로고·파비콘·푸터 서명·연습 결과 반응에만 캐릭터. 본문 제목은 "알아 두면 좋은 것", "티켓오픈 알림"처럼 중립.
- 지금처럼 유지하되 이름은 한 페이지에 한 번만.

### 4단계 — 손이 간 흔적 만들기 (지속)

AI 티를 없애는 가장 확실한 방법은 기계가 못 하는 것을 보여 주는 것이다.
1. 공연장 페이지에 직접 확인한 실용 정보: 가까운 출구 번호, 퇴장 동선, 물품 보관 — 확인한 날짜와 함께.
2. 공연 상세의 "확인한 날짜·출처" 줄을 더 앞으로. 지금도 있지만(11월 19일에 멜론티켓 예매 페이지에서 확인) 가격표 아래에 묻혀 있다. 이 사이트의 가장 큰 신뢰 장치다.
3. 셋리스트는 번호 목록 표준 형식으로 (A8). `docs/blog-post-rules.md` 5절에 형식을 적는다.
4. 정정 기록: 정보가 바뀌면 `updates`에 "무엇이 바뀌었고 언제 확인했는지"를 남긴다(UpdateLog가 이미 있다). 틀렸다가 고친 기록은 사람이 운영한다는 증거다.

### 5단계 — 남은 규칙 위반 정리 (틈날 때)

페이지에 직접 적은 색 300여 곳을 `:root` 변수로 옮긴다. `practice`·`ticketing-clock`·`EventCard`부터. 화면은 바뀌지 않지만 다음 개편 때 색이 흩어지지 않는다.

## 6. 결정이 필요한 것

1. 3단계 캐릭터 화법을 어느 쪽으로 할지.
2. 홈 알림 홍보 블록의 폰 목업을 남길지. 알림 기능을 설명하는 데는 실제 알림 캡처 한 장(목업 아닌 실물)이 더 믿을 만하다.
3. "가고 싶어요"와 찜을 합칠지. 둘이 어떻게 다르게 쓰이는지 집계가 있으면 그걸 보고 정한다.
