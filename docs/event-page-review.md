# 공연 상세 셀프 점검

공연 상세는 방문이 가장 많은 화면이다(최근 30일 페이지뷰의 43%, 2026-11-18). 사람이 일일이 지적하지 않아도 Claude가 스스로 점검하고 고친다.
디자인 취향이 아니라 **검색으로 처음 들어온 사람이 할 일을 끝낼 수 있는가**를 본다.

## 언제 하나

- 공연 상세 화면(`src/pages/events/[id].astro`와 그 안의 컴포넌트)을 고친 뒤
- 주간 트래픽 분석 때 방문 상위 공연을 대상으로

## 대상 고르기

최근 7일 공연 상세 방문 상위에서 상태가 다른 공연을 고른다. 상태마다 화면이 달라서 한 공연만 보면 문제를 놓친다.

- 티켓 오픈 전(카운트다운이 있는 공연)
- 예매 중
- 공연 7일 이내
- 판매 종료 또는 끝난 공연

## 1단계: 자동 점검

```bash
npm run build && npx astro preview --port 4321
node .claude/tools/shots/event-review.mjs http://localhost:4321 <출력 폴더> <공연 id> <공연 id>
```

휴대폰 화면 기준으로 아래를 잡는다. FAIL은 고친 뒤 다시 돌린다.

- 가로로 넘치지 않는다.
- D-day가 한 줄로 보인다.
- 예매할 수 있는 공연은 첫 화면에 예매 버튼이 보인다(하단 고정 버튼 포함).
- 포스터가 깨지지 않는다.
- 주요 버튼은 44px 이상이다.

## 2단계: 방문자 입장에서 캡처 읽기

캡처를 직접 열고, 검색으로 막 들어온 사람의 질문에 답이 있는지 본다.

1. 이 공연이 내가 찾던 공연이 맞나? (공연명, 날짜, 공연장)
2. 지금 살 수 있나? 언제 열리나? (예매 중, 오픈 전, 매진, 판매 종료)
3. 얼마인가? (가격이 있으면 3화면 안에 나오는가)
4. 어디서 사나? (예매처 상품 페이지로 바로 가는가)
5. 다음에 뭘 하면 되나? (같은 뜻의 버튼이 겹치지 않는가)

답이 틀리거나 없으면 화면보다 데이터부터 고친다(CLAUDE.md "공연 정보 보강").

## 3단계: 숫자로 확인

고친 효과는 `.claude/skills/traffic-feedback/SKILL.md`의 "성과 기준과 효과 판정"대로 판단한다. 기다리는 기간이 지나기 전에는 효과가 있다고 쓰지 않는다.

페이지별 예매 클릭률은 페이지의 목적에 따라 다르다. 셔틀 정보를 찾는 사람이 많은 공연은 예매 클릭이 적어도 정상이니, 예매·셔틀·그 밖의 클릭을 나눠서 본다.

## 사용자에게 묻는 것

아래만 묻고 나머지는 판단해서 고친다.

- 첫 화면 구성이 크게 바뀌는 개편
- 기능을 없애는 변경
- 캐릭터나 말투처럼 브랜드에 관한 결정
